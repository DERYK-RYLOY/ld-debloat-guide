START HERE01Read me first

What this is

A precision debloat of LDPlayer 9. It removes, disables or walls off every component whose job is advertising at the user, reporting on the user, or selling promoted games to the user, while leaving every component responsible for running games untouched.

What you will end with

No pop-ups. No featured-games wall. No install interception. No crash reporter. No auto-start service at logon. A guest sized for stability. And a small enforcement layer that re-applies the debloat automatically after updates, because LDPlayer updates re-ship its own bloat silently.

What you need

  • Windows with LDPlayer 9 installed (paths in this guide assume C:\LDPlayer\LDPlayer9).
  • Administrator rights. Right-clicking and choosing "Run as administrator" is enough; the scripts here self-elevate.
  • Roughly 90 minutes the first time. The hands-on work is ~15 minutes; the rest is understanding, so it never needs doing again.

What you will NOT get

This guide does not modify the Android image, game data, or Windows itself. It does not repack LDPlayer, does not bypass license checks, does not unlock paid features. It removes the advertising payload LDPlayer ships with because LDPlayer runs without it.

LDPlayer 9 installs with three classes of non-essential software. Know them by shape, not by file name: names change between builds, these classes do not.

Single most important fact: LDPlayer re-downloads Class 2 and 3 on launch and on update, forcibly. Any cleanup that runs only once is already undone by the second thing you do. Every fix in this guide is engineered against exactly that.

READ TWICE03The rules

RULE 1 — Rename first. Never delete. Every removal in this guide is a move, not a delete. If something breaks, you can reason back. You cannot reason back from a deletion.
RULE 2 — Read the logs, never guess. VBox.log, LD's own log files and the console output tell you what actually happened. If a change disappears, the log says why.
RULE 3 — Measure before you conclude. "The debloat broke the emulator" is never a starting point. Look first (VBox.log, pm list packages, verify-debloat.ps1), conclude second.
RULE 4 — Bisect with last-known-good. Change one variable at a time and re-test. Fancier fixes fail for teeny reasons, not grand ones.
RULE 5 — Verify before you destroy. If a verification step prints something odd, stop and look at it by hand. Unknown output is a red flag, not a green light.
RULE 6 — Never strip ACLs without setting replacements in the same move. Removing permissions outright can make a folder unreachable even for you. Always deny exactly one thing, replace nothing else.
RULE 7 — Pattern-match, never hardcode. LD renames its own packages between builds; grep for patterns, never a fixed string.
RULE 8 — Updates undo debloats. Plan for it. Every fix in this guide assumes an update will one day restore the bloat on its own. The logon task and the Clean Launch watcher exist precisely because updates always do.

KNOW YOUR SHIP04Know your target

Two minutes before you touch anything. This tells you exactly what this box is running.

& "C:\LDPlayer\LDPlayer9\ldconsole.exe" list
& "C:\LDPlayer\LDPlayer9\ldconsole.exe" list2
(Get-Item "C:\LDPlayer\LDPlayer9\dnplayer.exe").VersionInfo.ProductVersion
Get-Service LDPlayerENSvr | Select-Object Status, StartType
Get-CimInstance Win32_OperatingSystem | Select-Object @{n="FreeRAM_GB";e={[math]::Round($_.FreePhysicalMemory/1MB,2)}}
Get-ChildItem "C:\LDPlayer\LDPlayer9" | Sort-Object Length -Descending | Select-Object -First 8 Name, Length

What you are looking for

  • The LDPlayer version (file version of dnplayer.exe). Updates change what the bloat is called, never the classes above.
  • The instance count and state. Under C:\LDPlayer\LDPlayer9\vms\leidian0\ you will find one folder per instance.
  • LDPlayerENSvr — usually Auto; you will set it to Disabled on Step 7.
  • Two config files worth a look before editing anything: vms\config\leidians.config (update/telemetry pins) and vms\config\leidian0.config (instance CPU/RAM).
  • Shared folders — where LD exposes host folders to the guest: Documents\XuanZhi9\{Applications, Pictures, Misc}.
Stop and screenshot the launcher window (and the two config files) before you change anything. Not every problem goes away; but every problem becomes obvious after the first look.

THE MEAT05The Steps, 0–13

Difficulty: EASY · MEDIUM · HARD · EXPERT · Every command shown here works as printed. Where your install differs, change the path, not the shape of the step.

0The 30-second symptom check
EASY ~1 min risk: none

WHY

Confirm that the thing that is bugging you is LDPlayer and not Windows, your keyboard driver, or your browser.

LOOK FOR

  • Ads, recommendations or app-store suggestions inside the LDPlayer window you never asked for.
  • Desktop pop-ups when LDPlayer is not running.
  • Slow boots into the guest or a guest that freezes at roughly the same second on every cold boot.

IF YES

Proceed. If none of those apply, close this guide — you do not have the disease it treats.

EASY ~2 min risk: none

DO THIS

New-Item -ItemType Directory -Force -Path C:\LDPlayer | Out-Null

3Wave 1 — vault the classic bloat
EASY ~3 min risk: none — moves only, zero deletes

WHAT IT DOES

reapply-debloat.ps1 moves the known offenders into a timestamped vault folder. It never deletes — if something breaks, the files are visible, named and in one place.

powershell.exe -NoProfile -ExecutionPolicy Bypass -File C:\LDPlayer\reapply-debloat.ps1

EXPECTED RESULT

Lines like vaulted: ...\ldplayerpartner.exe and ad cache sealed (deny Everyone write). Then re-run Step 1's verifier and watch every line flip to [PASS].

4Seal the ad cache
MEDIUM ~3 min risk: low

THE WHY

The cache folder is where the current ad payloads are kept between launches. Emptying alone is not enough — LDPlayer re-downloads them. A deny-write ACE makes the folder permanently useless to it.

WHAT THE SCRIPT DOES

reapply-debloat.ps1 already performs this — moves contents into the vault, then adds a single Deny ACE: Everyone, Write, inherited by children. Nothing else in the ACL is touched.

Verified: after the seal, a file write to the cache fails with access denied. If it does not, your account is not elevated — re-run as administrator.
5Re-pin update & telemetry timestamps
MEDIUM ~2 min risk: low

THE WHY

leidians.config holds timestamps that tell LDPlayer when to call home and when to look for an update. Its update re-arms these to "now" on every install; the script pins them to 2100 again.

powershell -ExecutionPolicy Bypass -File C:\LDPlayer\reapply-debloat.ps1

Expected: leidians.config pins re-applied (present keys only). Keys that do not exist in your LDPlayer version are skipped rather than invented.

Note: this step is idempotent and also self-healing — it is re-applied at every run of the reapply script, so an update re-arming the pins is defeated automatically.
6CPU & RAM tuning — the 3072 rule
HARD ~10 min + one test boot risk: medium

THE RULE

Give the guest no more than ~40% of host memory when anything else is running (a browser tab, a game, an IDE) — and no more than ~50% ever. On a memory-tight box that is almost always 2048–4096 MB depending on hardware. 3072 MB with 3 CPUs is the measured sweet spot for an 8 GB host.

HOW

The script sets CPU back to 3 with LD's own ldconsole:

& "C:\LDPlayer\LDPlayer9\ldconsole.exe" modify --index 0 --cpu 3

Memory is set inside leidian.vbox (RAMSize value) and is written out by LD on launch, so do not edit it while LDPlayer is running.

WHY IT IS THE HARDEST STEP

Machines that are not memory-constrained pass Step 6 painlessly; machines that are will boot-slow or wedge until the memory is lowered. If Boot loops twice identically, reduce by 512 MB and test again.

7Kill the service
MEDIUM ~2 min risk: low

WHY

LDPlayerENSvr (name varies by build — LDPlayerENSvc / LDPlayerServiceEN also appear) auto-starts the launcher plumbing. It is not required for the emulator to run; it is the delivery mechanism for the ad channels.

Get-Service LDPlayerENSvr -ErrorAction SilentlyContinue | Select-Object Status, StartType
Stop-Service LDPlayerENSvr -Force -ErrorAction SilentlyContinue
Set-Service LDPlayerENSvr -StartupType Disabled

The reapply script does the same thing with tolerance for missing services.

8Network layers: hosts + firewall
MEDIUM ~4 min risk: low

LAYER A — marked hosts block

Ten domains map to 0.0.0.0 under a fence. Nothing else in the file changes:

$block = @"

# LDPlayer-Debloat-Block-Begin (LDPlayer ad/telemetry endpoints)
0.0.0.0 ldrescdn.com
0.0.0.0 res.ldrescdn.com
0.0.0.0 img.ldrescdn.com
0.0.0.0 tj.ldmnq.com
0.0.0.0 ad.ldmnq.com
0.0.0.0 ads.ldplayer.net
0.0.0.0 report.ldmnq.com
0.0.0.0 alog.ldmnq.com
0.0.0.0 data.ldplayer.net
0.0.0.0 res.ldplayer.net
# LDPlayer-Debloat-Block-End
"@
[IO.File]::AppendAllText("C:\Windows\System32\drivers\etc\hosts", $block, (New-Object Text.ASCIIEncoding))

LAYER B — program-scoped firewall blocks

Five outbound Block rules named LDPlayerBlock-*, one per ad/telemetry executable. Because they are scoped by program path, LD's next update cannot rotate the domains past them.

Both layers are applied automatically by reapply-debloat.ps1. No extra command is needed.

9Wave 2 — the deep sweep
MEDIUM ~10 min risk: low

WHY

The "classic" cleanup covers the advertised files; the install root ships a second telemetry stack that classic guides never look at. reapply-debloat.ps1 removes them too:

  • upload\ — a Huawei OBS crash-telemetry SDK (ldupload.exe + associated DLLs). Vaulted wholesale; firewall-blocked in Step 8.
  • Manager's bugreport.exe — a second reporter beside the one in LDPlayer9. Found only by inventoring the whole tree.
  • App-store intercept feed — Documents\XuanZhi9\Applications\ld_launcher\ + cpi.data + a fetch-stamp (hex-named). Redirects Google Play installs to the LD-store.
  • Recommendation DB — vms\recommendConfigs\dir_*.dir + package_configs_1005*. Game suggestions with ad placements.
  • partner_report.data — the 10-byte file that witnesses the last successful report POST.

Every one of these is re-vaulted automatically at each run of the reapply script.

10Permanence — the logon enforcement task
HARD ~5 min risk: low

WHY

Updates restore everything you removed — not because they are malicious, because LD ships in one piece and the update is that piece. A logon-triggered hidden task re-runs the reapply script so the debloat survives updates indefinitely.

$action = New-ScheduledTaskAction -Execute 'powershell.exe' -Argument '-NoProfile -ExecutionPolicy Bypass -WindowStyle Hidden -File C:\LDPlayer\reapply-debloat.ps1'
$trigger = New-ScheduledTaskTrigger -AtLogOn -User "$env:USERDOMAIN\$env:USERNAME"
$principal = New-ScheduledTaskPrincipal -UserId "$env:USERDOMAIN\$env:USERNAME" -RunLevel Highest -LogonType Interactive
$settings = New-ScheduledTaskSettingsSet -AllowStartIfOnBatteries -DontStopIfGoingOnBatteries -ExecutionTimeLimit (New-TimeSpan -Minutes 5) -Hidden
Register-ScheduledTask -TaskName 'LDPlayerDebloatEnforce' -Action $action -Trigger $trigger -Principal $principal -Settings $settings -Force

PROVE IT

Start-ScheduledTask -TaskName 'LDPlayerDebloatEnforce'
(Get-ScheduledTaskInfo -TaskName 'LDPlayerDebloatEnforce').LastTaskResult

Expect 0.

12Inside Android (ADB)
EXPERT ~15 min risk: medium

WHY THIS IS A SEPARATE STEP

Steps 1–11 fix Windows-side plumbing. The LD-store engine lives inside the guest, and only answers to ADB. An update can also reset the in-guest changes on re-image, so this step is rerunnable by design.

1 — Enable ADB debugging

LDPlayer → gear icon → Other → ADB debugging: ON. If this is off, every command below returns nothing. Every LD update turns it back off.

2 — Install the replacements

& "C:\LDPlayer\LDPlayer9\adb.exe" install -r "C:\ld-apps\Lawnchair.apk"
& "C:\LDPlayer\LDPlayer9\adb.exe" install -r "C:\ld-apps\Aurora.apk"
& "C:\LDPlayer\LDPlayer9\adb.exe" install -r "C:\ld-apps\Magisk.apk"

Pickers for the APKs: Lawnchair 1.2.0 → github.com/LawnchairLauncher/lawnchair/releases  ·  Aurora Store → f-droid.org/packages/com.aurora.store  ·  Magisk → github.com/topjohnwu/Magisk/releases. Verify package names with aapt dump badging before installing anything.

3 — Disable LD's own apps (matched by name pattern)

& "C:\LDPlayer\LDPlayer9\adb.exe" shell cmd package disable-user --user 0 com.ldmnq.launcher3
& "C:\LDPlayer\LDPlayer9\adb.exe" shell cmd package disable-user --user 0 com.android.ld.appstore

4 — Home screen

& "C:\LDPlayer\LDPlayer9\adb.exe" shell cmd package set-home-activity ch.deletescape.lawnchair/ch.deletescape.lawnchair.Launcher

5 — Ad-blocking DNS

& "C:\LDPlayer\LDPlayer9\adb.exe" shell settings put global private_dns_mode hostname
& "C:\LDPlayer\LDPlayer9\adb.exe" shell settings put global private_dns_specifier dns.adguard.com

6 — The one step that is yours alone

Magisk → Install → Direct install → Reboot. Until this is done, su -c id correctly reports root not live.

13Live clean forever
EASY ~2 min per update risk: none

THE ROUTINE

  1. Open LDPlayer exclusively via the Clean Launch shortcut, never the stock icon.
  2. Close what you are not actively using — LD will take whatever memory it is left.
  3. After any LDPlayer update: log off and back on, then run both verifiers. Any FAIL is fixed by re-running reapply-debloat.ps1 and android-refresh.ps1.
  4. Thirty quiet days in a row: delete C:\LDPlayer\vault to reclaim disk.

THE CLEAN LAUNCH SHORTCUT

clean-launch.ps1 debloats, launches LDPlayer, then re-sweeps 75 seconds later — after the launch-time re-download lands. One double-click, nothing else.

powershell.exe -NoProfile -ExecutionPolicy Bypass -File C:\LDPlayer\clean-launch.ps1

Make it a shortcut on the desktop (right-click → New → Shortcut → paste powershell.exe -NoProfile -ExecutionPolicy Bypass -WindowStyle Hidden -File C:\LDPlayer\clean-launch.ps1) and bind the stock LDPlayer icon to it.

WHEN THINGS BREAK06Errors & fixes

The two classes (learn to tell them apart)

CLASS A — Deterministic: same spot, same signature, two times in a row (an admin refusal; a boot wedge at the same second). It never fixes itself. Change the variable, not your mood.
CLASS B — Load-dependent: only happens when the machine is saturated (a game, a browser, an IDE and LD competing for the same memory). It is not a bug; it is arithmetic. Step 6 exists for exactly this class.

SPEAK THE LANGUAGE09Glossary

A–C

ACE — a single permission rule inside a file/folder's ACL. We use one deny-write ACE.
ACL — the rule list that says who may read, write or run an object.
ADB — Android Debug Bridge: the wire that lets your PC talk into the emulator.
Aurora Store — clean front-end for Play.
App-store intercept — LD-store redirect rules for Google Play installs (Class 2).

D–H

dnplayer — LDPlayer's engine (VirtualBox-based).
Disable-user — Android's drop-in replacement for "uninstall a system app for this user".
Direct install — Magisk's button that patches the boot image; without it root does not exist.
Emulator — the running Android inside LDPlayer.
exit code — a number a program returns; 0 = fine.

I–L

Idempotent — running it again changes nothing.
interceptTiming — inside LD's JSON: when to hijack.
LD-store — LD's own app store; where intercepts are sent.
Launcher — the Android home-screen app (Lawnchair is the replacement).

M–Z

Magisk — root manager.
Private DNS — forces DNS through your chosen (ad-blocking) resolver.
Private DNS specifier — the hostname of that resolver (dns.adguard.com).
Recommendation DB — dir_*.dir: "great games for you" with ads.
The pin — the far-future timestamps in leidians.config.
ldmarket:// — the LD-store URI scheme.
VBox.log — the VM's flight recorder; read it when boots fail.

YOUR QUESTIONS, ANSWERED10FAQ

Will this make my games faster?

Indirectly. The elimination of ad processes, telemetry and re-downloads removes background drains; the 3072 MB/3-CPU rule stops swap when other apps are running; removing the intercept feed means your apps come from Play, not from LD's clone. None of those are frame-rate tools, and none promise you will suddenly get 240 FPS.

Is this legal? Did we crack anything?

No patching, repacking or DRM circumvention happens anywhere. We move extra files (reversible), flip LDPlayer's own settings, and use standard Windows firewall/hosts rules. It runs LDPlayer with fewer passengers, not a different LDPlayer.

Will LDPlayer still update?

LD always ships as one piece; any update reintroduces the bloat. The Clean Launch watcher and the logon task re-apply the debloat automatically. Disabling the in-guest feed means the update itself installs faster and draws less.

Why the one firewall rule per executable instead of blocking domains?

Domains rotate; executable paths do not, until the next LD build reinstalls them — at which point the old rules silently re-apply (path unchanged) and you win again without any new work.

My friend says "everything came back after the update". Why?

Because their cleanup ran once, as a single pass. This is why Step 10 and Step 13 exist — the fix is a loop, not an event.

I'm not technical. Which steps can I skip?

Steps 0–11 are mechanical. Never skip Step 12 if you care about the in-guest ads, and Step 10 if you care about updates keeping it that way.

Magisk asked to Direct install; do I have to?

Yes — Magisk's binary lives in the boot image; the manager alone does not patch it. Without Direct install, su exists but root never fires.

Can LDPlayer detect that I debloated it?

Yes, in the same sense it can detect you removed an uninstaller. It does not phone home about it, and it does not lock features. The bloat is gone, LD still runs, support still works.

Where is LD's official FAQ for all this?

There is none. What you just read was produced by doing it carefully, watching what came back, and keeping what proved necessary.

THE HOST OS11Windows 10 Lite — what is added, what is not

Some Windows builds are thinned by third parties ("Lite", "Tiny10", handcrafted ISOs). This guide never touches those' Windows: no system files, no shell, no services outside LDPlayer's, no removal of anything host-side except LDPlayer's own binaries.

THE MODEL12Why it survives updates

LDPlayer is one piece of software that re-ships its full runtime on every update. When the update runs, it copies in whatever it ships — bloat and all — and re-enables what you disabled. That is not a hostile fork; it is simply how LDPlayer is built. So the fix is not an event; it is a standing invariant:

The three-move loop: (1) at logon, a hidden task re-vaults anything restored and re-pins; (2) at launch, the Clean Launch shortcut re-vaults whatever re-downloaded during startup; (3) both verifiers tell you whether the invariant held. That is the entire permanence model.

What survives, what does not

SurvivesDoes NOT survive
Windows-internal edits: hosts block, firewall rules, service start typeGuest-internal edits (packages disabled, HOME setting) — they live in data.vmdk and survive updates unless the update re-images it
The pinned update timestampsThe launch-time feed download — it re-arrives on every launch until the watcher re-vaults it
The seal on the cache folderThe installer stub — it always re-appears; the reapply script always removes it

How to keep the invariant

  1. Never launch LDPlayer via the stock icon. Launch via the Clean Launch shortcut.
  2. After every update, log off and back on. The logon task fires.
  3. Run both verifiers. They tell you whether the loop held.

  $hit = Get-ChildItem 'C:\LDPlayer' -Directory -Force -ErrorAction SilentlyContinue | Where-Object { Test-Path (Join-Path $_.FullName 'adb.exe') } | Select-Object -First 1
  if ($hit) { $LD_ROOT = $hit.FullName }
}
$adb = "$LD_ROOT\adb.exe"
$fails = 0
function Report($l){ Write-Host $l }
function Verify($name, [scriptblock]$test){
  $ok = $false
  try { $ok = [bool](& $test) } catch { $ok = $false }
  if ($ok) { Report "[PASS] $name" } else { Report "[FAIL] $name"; $script:fails++ }
}

$dev = (& $adb devices | Out-String)
if ($dev -notmatch 'emulator-\d+\s+device') { Report 'SKIP: no emulator attached (start it, then re-run)'; exit 0 }
Report "ADB: connected ($LD_ROOT)"

$thirdParty = (& $adb shell pm list packages -3 | Out-String)
$disabled   = (& $adb shell pm list packages -d | Out-String)
$dns        = (& $adb shell settings get global private_dns_specifier | Out-String).Trim()
$mode       = (& $adb shell settings get global private_dns_mode | Out-String).Trim()
$home       = (& $adb shell cmd package resolve-activity --brief -a android.intent.action.MAIN -c android.intent.category.HOME | Out-String).Trim()

Verify 'Lawnchair installed'          { $thirdParty -match 'ch.deletescape.lawnchair' }
Verify 'Aurora Store installed'       { $thirdParty -match 'com.aurora.store' }
Verify 'Magisk installed'             { $thirdParty -match 'com.topjohnwu.magisk' }
Verify 'Private DNS = adguard'        { $dns -eq 'dns.adguard.com' -and $mode -eq 'hostname' }
Verify 'Lawnchair is HOME'            { $home -match 'ch\.deletescape\.lawnchair' }

foreach ($pat in @('launcher3','ld.appstore')) {
  $present = (& $adb shell pm list packages | Out-String) -match [regex]::Escape($pat)
  $dis = $disabled -match [regex]::Escape($pat)
  if ($present) { Verify "LD package ($pat) disabled" { $dis } }
}
$all = (& $adb shell pm list packages | Out-String) -split "`n" | ForEach-Object { $_ -replace 'package:','' } | ForEach-Object { $_.Trim() } | Where-Object { $_ }
$anythingSuspicious = $false
foreach ($p in $all) {
  if ($p -match 'ldmnq|\.ld(-|\.|$)|ldupload|ldperfect') { $anythingSuspicious = $true }
}
Verify 'no obvious LD-promoted packages remain' { -not $anythingSuspicious }

if ($fails -eq 0) { Report 'RESULT: ALL ANDROID CHECKS PASSED' } else { Report "RESULT: $fails problem(s) found" }
exit $fails
